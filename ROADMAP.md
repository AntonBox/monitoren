## M4 — Functional slider

- [x] Replace mock backend with the verified HDR-preserving SDR controller only when supported (approved scope adaptation).
- [x] Show actual brightness where possible; errors are visible.
- [x] Serialize brightness writes, coalesce rapid slider events, keep UI responsive.
- [x] Normalize the approved application range, clamp requests and use a 10% UI safety floor initially.
- [x] Popup behaves correctly on scaling changes / screen edges as reasonably possible.

**Manual gate:** slow and fast slider drags do not freeze UI or flood monitor; last requested value wins; error state readable.

M4 implementation: the popup now has one functional 10-100% desktop brightness
slider, a reported monitor name, confirmation checkbox, Read / Refresh button,
actual percentage, and a selectable error/status box. Opening for the first time
requires explicit confirmation of the sole AOC HDMI target, then a read. Later
reopens refresh the current value. Programmatic slider updates never write.

Writes use a 200 ms debounce window, discard obsolete pending positions, run
through the shared native worker queue and verify read-back. A newer request
during slow I/O wins; stale results do not overwrite the latest UI request.
Identity/HDR changes, failed calls and mismatched read-back disable control and
drop queued writes. Reconnection requires explicit confirmation and a read.
Exit cancels queued changes, awaits an in-flight call, and releases the session;
no automatic restoration is performed. Popup close keeps the app alive.

The completed M3 test window was removed from the tray menu to prevent two
brightness controllers from interfering. Its source and regression checks remain.
No hotkeys, settings, persistence, HDR toggle, or gamma control was added. Popup
position is clamped to the working area and rechecked after DPI changes.
See [M4 manual checks](docs/M4-slider-test.md).

M4 automated verification: final Debug `dotnet build` succeeded with 0 warnings
and 0 errors. All 19 M4 simulated controller checks and all 45 existing M3

## M5 — Global hotkeys

- [x] Register global increase/decrease hotkeys via Win32 `RegisterHotKey`, process `WM_HOTKEY`.
- [x] Use same monitor target, min/max, and request queue as slider.
- [x] Default candidates `Ctrl+Alt+Shift+PageUp/PageDown` if available.

**Manual gate:** with another application focused, hotkeys change only selected monitor; no action after Exit.

M5 implementation (2026-10-22): Ctrl+Alt+Shift+PageUp/PageDown request +5/-5
percentage points using the existing confirmed SDR target and serialized queue.
A dedicated message-only window receives WM_HOTKEY while the popup is hidden.
MOD_NOREPEAT makes holding a key a single step. Rapid presses accumulate from
the latest requested value, including during an in-flight write; fractional
readings are retained. Slider requests and hotkeys share clamping and read-back.
Opening/refreshing reads the actual value and resets the starting point.

Registration failures report the shortcut and Win32 error through Hotkeys... in
the tray menu, a popup label and a notification. Partial registration is rolled
back so a failed pair does not act. Exit unregisters both keys before stopping
brightness work; queued notifications cannot request new writes. Startup,
registration and unconfirmed key presses do not read or write display brightness.
No new settings, packages, persistence, hardware backend or Git commit added.
