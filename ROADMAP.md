# Roadmap — one milestone per agent request

The checkbox can be marked completed **only after the user has confirmed manual tests**. Each stage should leave a buildable Windows application. Do not work ahead.

## M0 — Environment, repository, scaffold

- [ ] Confirm developer is working on Windows 10/11; capture `dotnet --info`, `dotnet new list`, `git --version`.
- [ ] Initialize local Git repository if absent; make initial commit after user approval.
- [ ] Create `.sln` (or `.slnx` if generated by SDK) + WinForms app using `.NET 10` (`net10.0-windows`) and `UseWindowsForms=true`.
- [ ] Change starter form to minimal app window only if necessary. Do not add DDC or hotkeys.
- [ ] `dotnet build` succeeds, `dotnet run` starts the initial app.

**Manual gate:** app visibly starts on Windows; no DDC hardware changes.

## M1 — Tray shell with no monitor access

- [ ] Replace visible default main window with `ApplicationContext`, `NotifyIcon`, context menu.
- [ ] Left click tray icon opens/closes a tiny popup with **mock brightness slider** explicitly labeled demo.
- [ ] Right click -> Exit really closes process; popup close does not exit process.
- [ ] No duplicate tray icons after relaunch. Build clean.

**Manual gate:** test tray and Exit (Task Manager if necessary); screenshot popup; no real monitor changes.

## M2 — Read-only DDC/CI diagnostics

- [ ] Implement native declarations for monitor enumeration, acquiring physical monitors, reading capabilities + brightness, and releasing handles.
- [ ] Diagnostic action lists logical/physical monitor identification, DDC/CI read support, min/current/max, errors.
- [ ] Clearly distinguish selected HDMI/external monitor from laptop internal panel as far as API identification allows; require explicit selection if ambiguous.
- [ ] **No SetMonitorBrightness/SetVCPFeature call yet**.
- [ ] Log user-safe diagnostic output or offer Copy Diagnostics button.

**Manual gate:** user sends enumeration results; knows exactly which target monitor is selected and whether it responds to DDC reads. If no DDC support, **stop** and reassess.

## M3 — First controlled hardware change

- [ ] Add a single, user-invoked 'Test brightness' action for the manually selected monitor only.
- [ ] Read brightness -> change by a **small** amount (e.g. 5 percentage points within range) -> confirm actual new value -> provide Restore button.
- [ ] No automatic changes at app startup; no silent retries.
- [ ] Handle errors and close native handles. No background loop.

**Manual gate:** user verifies that *physical brightness* of chosen external monitor changes and Restore works. Do not continue if display identity or DDC behavior is uncertain.

## M4 — Functional slider

- [ ] Replace mock backend with hardware controller only when supported.
- [ ] Show actual brightness where possible; errors are visible.
- [ ] Serialize DDC writes, coalesce rapid slider events, keep UI responsive.
- [ ] Normalize device range, clamp requests and configure minimum UI safety floor 10% initially.
- [ ] Popup behaves correctly on scaling changes / screen edges as reasonably possible.

**Manual gate:** slow and fast slider drags do not freeze UI or flood monitor; last requested value wins; error state readable.

## M5 — Global hotkeys

- [ ] Register global increase/decrease hotkeys via Win32 `RegisterHotKey`, process `WM_HOTKEY`.
- [ ] Use same monitor target, min/max, and request queue as slider.
- [ ] Default candidates `Ctrl+Alt+Shift+PageUp/PageDown` if available.
- [ ] Report conflicts, release registrations on Exit.

**Manual gate:** with another application focused, hotkeys change only selected monitor; no action after Exit.

## M6 — Settings, persistence, robustness

- [ ] Settings UI: monitor selection, step size (default 5%), hotkeys, optional safety minimum.
- [ ] Store JSON in `%LOCALAPPDATA%\MonitorBrightness\settings.json`.
- [ ] Handle invalid JSON and monitor unplug/replug, do not silently act on wrong monitor after topology change.
- [ ] Ensure app exits cleanly and handles failures without crashes.
- [ ] Consider single-instance implementation; no forced termination.

**Manual gate:** restart app, preferences persist, external display disconnect/reconnect does not change the wrong display.

## M7 — Release

- [ ] Build Release, run available automated tests, manual smoke check on Windows.
- [ ] Publish **self-contained single-file** for `win-x64` first without trimming.
- [ ] Test the published EXE (not just `dotnet run`) on Windows and confirm Exit.
- [ ] Write README with build, usage, limitations, and known DDC compatibility caveats.
- [ ] Only after separate approval: consider optional auto-start. Never modify startup configuration silently.

**Suggested commands (run on Windows in the app project or solution directory):**

```powershell
dotnet build -c Release
dotnet publish .\MonitorBrightness\MonitorBrightness.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:PublishTrimmed=false
```

Note: the actual project path may differ. Self-contained single-file may be fairly large. `PublishTrimmed` remains false for WinForms compatibility.

## Nice-to-have V2 (do NOT implement in V1)

- Multi-monitor control independently (requires reliable identity mapping).
- Quick 25/50/75 presets.
- Optional startup with Windows after opt-in.
- Better dark theme, localization.
- Explicit user-approved software brightness fallback if monitor DDC/CI is unsupported.
